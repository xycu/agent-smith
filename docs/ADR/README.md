# Architecture decision records

One row per ADR, with the decision in one line. Read the file for the context, the rules (written as scenarios, ADR-004) and the open questions. A new ADR gets its row here, not in `AGENTS.md`.

| ADR | Title | Summary |
| --- | --- | --- |
| [ADR-001](ADR-001-phased-complexity-routing.md) | Phased complexity routing | Deterministic routing and measured churn shipped. ADR-007 brought scoring forward. The original static risk levels remain a proposal. |
| [ADR-002](ADR-002-change-lifecycle-ideation-to-archive.md) | Change lifecycle | The toolkit lifecycle maps ideation through archive. The shipped pipeline runs a subset, with opt-in archive and terminal publication for isolated runs. |
| [ADR-003](ADR-003-rigor-gated-routing.md) | Rigor-gated routing | Rigor and measured churn control optional work, budget and effort. Isolated step commits, Manual verification, terminal publication and saved PR-comment intent apply. |
| [ADR-004](ADR-004-prompt-rules-as-scenarios.md) | Prompt rules as scenarios | Every behavior rule in a prompt is one **GIVEN** / **WHEN** / **THEN** line with one RFC 2119 keyword; `rules.test.mjs` checks the form |
| [ADR-005](ADR-005-baseline-usage-comparison.md) | Baseline usage comparison | The read-only comparison uses a pinned baseline checkout and checks usage coverage. Legacy-only totals carry a warning and mixed verified/legacy coverage precludes a savings verdict. |
| [ADR-006](ADR-006-node-runtime-floor.md) | Node runtime floor | The floor is Node 24, the oldest line with more than a year of security support; the router uses only `node:` built-ins |
| [ADR-007](ADR-007-llm-complexity-scorer-as-a-routed-step.md) | LLM complexity scorer | Complexity is scored by a cheap-model `score` step the router schedules and reads from `complexity.json`; the router stays a script with no LLM call |
| [ADR-008](ADR-008-release-packaging-and-semver.md) | Release packaging and SemVer | Releases by release-please in the release-PR model from Conventional Commits, one version in three fields, a drift guard and a commit lint. Amendment 1: release only after a green CI run of `main`. Amendment 2: squash-only merging, PR title lint. Amendment 3: no version in the marketplace plugin entry |
| [ADR-009](ADR-009-managed-agent-patterns.md) | Provenance, restricted agents, advisor | Records run provenance in `meta.json`, opts in to tool-restricted step agents (`agents.restricted`) and to the advisor flag (`advisor.enabled`, `prompts/advisor.md`); the router stays a script. Amendment 1 records the guarded Claude default and hook provenance. |
| [ADR-010](ADR-010-run-worktree-step-commits-and-rollback.md) | Run worktree, step commits, rollback | Shared setup validates the configured branch and uses lock-free pending checks with one staging file per branch. The router commits verified changes, reports swept paths and preserves distinct staged and working versions before rollback. Isolation can be disabled. |
| [ADR-011](ADR-011-route-reviews-on-open-findings.md) | Reviews on open findings | A plan review `REVISE` and an implementation review `NEEDS ATTENTION` are routed on open findings; a pending owner decision halts; an opt-in confirmation round re-checks applied fixes |
| [ADR-012](ADR-012-automate-manual-checks.md) | Automate Manual checks | Manual verification attempts every pending row at all default rigor levels, records proof or a reason, and can retry outside the extra-step pool. Browser rows require browser, test, command or script evidence. |
| [ADR-013](ADR-013-openspec-pipeline.md) | OpenSpec pipeline | Chain-local policy, definitions and prompts share a file-reading router. Contract fixtures check OpenSpec 2.0.0 exactly. |
| [ADR-014](ADR-014-archive-manual-gate.md) | Archive Manual gate | The orchestrator asks a yes/no question before an `--archive` run archives with Manual rows pending |
| [ADR-015](ADR-015-neutral-orchestrator-retry.md) | Neutral orchestrator retry | The `orchestrator-error` result reruns the step unchanged from its stored `pendingPrompt`, with no failed attempt, capped per step by `limits.maxNeutralRetries` |
| [ADR-016](ADR-016-no-recursive-force-delete.md) | No recursive or forced delete | No recursive or forced directory delete in code, tests, skills, prompts or docs; list, check, delete one by one, then `rmdir`; `removeTree` is the one way. The prompt rules live in `rules/top.md` (ADR-023). Amendment 1 adds scoped Claude direct-shell enforcement and coverage limits. |
| [ADR-017](ADR-017-run-branch-always-pushed-for-review.md) | Run branch pushed for review | `open-pr.mjs` pushes the run branch (never with force) and opens its pull request at every end of a run, never merging; `isolation.require: false` is the only exception. Amendment 1: conventional run PR title. Amendment 2 assigns step publication and pre-publication acceptance ownership. Amendment 3 publishes validated configured branches with literal recovery arguments. |
| [ADR-018](ADR-018-no-nested-subagents.md) | Bounded native children | One awaited native child layer inherits step restrictions. The enclosing step collects every child, matches the result to its invocation and accounts for attributable usage once. |
| [ADR-019](ADR-019-late-usage-figure.md) | Late usage figure | After settlement, the router can attach a legacy figure or fill missing tokens with matched structured evidence. Archive-state attachment commits the refreshed log and report. |
| [ADR-020](ADR-020-ci-on-self-hosted-truenas-runners.md) | CI on self-hosted runners | CI uses TrueNAS with a hosted fallback for fork pull requests and a repository approval gate. Amendment 3 disables OpenSpec install scripts and records the runner trust boundary. |
| [ADR-021](ADR-021-agent-smith-co-author.md) | Agent Smith co-author | Every router commit and the leftover commit of `open-pr.mjs` carry a `Co-Authored-By: Agent Smith` trailer from the policy key `coAuthor` (`null` turns it off) |
| [ADR-022](ADR-022-policy-validation-at-load.md) | Policy validation at load | The keys that cap spend and the prompt placeholders fail closed in `init`, `next` and `usage`; `status` reports `policyProblem`; `baseTier` may lie outside its bounds; `limits.maxNeutralRetries` is strict |
| [ADR-023](ADR-023-layered-rules.md) | Layered rules | Rules come in three levels (top, chain, step) and two categories: always-true rules in `<skill>/rules/` files that the router reads by fixed path and no override reaches, and overridable defaults in policy keys; `rules/top.md` ends every prompt with the precedence rules and the `RESULT:` format. Amendment 1 names shared safety and planning step owners. |
| [ADR-024](ADR-024-openai-codex-support.md) | OpenAI Codex support | Fixed host and mode select a provider per role. The standalone Codex and headless Claude runners validate dispatch and settle native descendants with transport-specific usage evidence. Amendment (2026-11-24): the Codex runner grants write on the run root's own gitdir to the resolved permissions profile (`codex.permissions`). Amendment (2026-11-24): the grant adds the common dir's `objects`, `refs` and `logs`, never `hooks` or `config`, and `init` lists stale per-worktree lines. |
