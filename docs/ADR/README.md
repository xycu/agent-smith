# Architecture decision records

One row per ADR, with the decision in one line. Read the file for the context, the rules (written as scenarios, ADR-004) and the open questions. A new ADR gets its row here, not in `AGENTS.md`.

| ADR | Title | Summary |
| --- | --- | --- |
| [ADR-001](ADR-001-phased-complexity-routing.md) | Phased complexity routing | Route model and effort from cheap deterministic signals first (phase count, goal text, diff files, review verdicts, failed attempts); path rules mark risk; scored complexity only if data demands it (partly superseded by ADR-007) |
| [ADR-002](ADR-002-change-lifecycle-ideation-to-archive.md) | Change lifecycle | One canonical lifecycle from ideation to archive: a three-step mandatory core (plan, one executor, archive), every other step optional with an entry trigger; files carry state |
| [ADR-003](ADR-003-rigor-gated-routing.md) | Rigor-gated routing | A per-change rigor level (`lean`, `standard`, `thorough`) decides the optional steps, the step budget and the effort floor; split into five changes |
| [ADR-004](ADR-004-prompt-rules-as-scenarios.md) | Prompt rules as scenarios | Every behavior rule in a prompt is one **GIVEN** / **WHEN** / **THEN** line with one RFC 2119 keyword; `rules.test.mjs` checks the form |
| [ADR-005](ADR-005-baseline-usage-comparison.md) | Baseline usage comparison | The baseline arm is data (`baseline-policy.json` in a second checkout) and `compare` is a read-only command over two run folders, decided on raw tokens |
| [ADR-006](ADR-006-node-runtime-floor.md) | Node runtime floor | The floor is Node 24, the oldest line with more than a year of security support; the router uses only `node:` built-ins |
| [ADR-007](ADR-007-llm-complexity-scorer-as-a-routed-step.md) | LLM complexity scorer | Complexity is scored by a cheap-model `score` step the router schedules and reads from `complexity.json`; the router stays a script with no LLM call |
| [ADR-008](ADR-008-release-packaging-and-semver.md) | Release packaging and SemVer | Releases by release-please in the release-PR model from Conventional Commits, one version in three fields, a drift guard and a commit lint. Amendment 1: release only after a green CI run of `main`. Amendment 2: squash-only merging, PR title lint. Amendment 3: no version in the marketplace plugin entry |
| [ADR-009](ADR-009-managed-agent-patterns.md) | Provenance, restricted agents, advisor | Records run provenance in `meta.json`, opts in to tool-restricted step agents (`agents.restricted`) and to the advisor flag (`advisor.enabled`, `prompts/advisor.md`); the router stays a script |
| [ADR-010](ADR-010-run-worktree-step-commits-and-rollback.md) | Run worktree, step commits, rollback | Every change runs in its own worktree, each step is committed, a failed step is rolled back (the worktree is snapshotted under `refs/agent-smith/` first), the ladder has the `opus/medium` rung, and the first implement attempt is cheaper. Amendment 1: the paths a step commit takes from outside the change folder |
| [ADR-011](ADR-011-route-reviews-on-open-findings.md) | Reviews on open findings | A plan review `REVISE` and an implementation review `NEEDS ATTENTION` are routed on open findings; a pending owner decision halts; an opt-in confirmation round re-checks applied fixes |
| [ADR-012](ADR-012-automate-manual-checks.md) | Automate Manual checks | `manual-verify` proves every Manual row at every rigor level, outside the extra-step pool, with a retry one tier up, evidence kinds, unproved reasons and Chrome on by default. Amendment 1: a browser row needs browser, test, command or script evidence |
| [ADR-013](ADR-013-openspec-pipeline.md) | OpenSpec pipeline | A second pipeline skill shares the router: the `--chain` switch, file-based reading of OpenSpec state, the `verify.md` verdict, the fix loop and the archive through the OpenSpec CLI |
| [ADR-014](ADR-014-archive-manual-gate.md) | Archive Manual gate | The orchestrator asks a yes/no question before an `--archive` run archives with Manual rows pending |
| [ADR-015](ADR-015-neutral-orchestrator-retry.md) | Neutral orchestrator retry | The `orchestrator-error` result reruns the step unchanged from its stored `pendingPrompt`, with no failed attempt, capped per step by `limits.maxNeutralRetries` |
| [ADR-016](ADR-016-no-recursive-force-delete.md) | No recursive or forced delete | No recursive or forced directory delete in code, tests, skills, prompts or docs; list, check, delete one by one, then `rmdir`; `removeTree` is the one way |
| [ADR-017](ADR-017-run-branch-always-pushed-for-review.md) | Run branch pushed for review | `open-pr.mjs` pushes the run branch (never with force) and opens its pull request at every end of a run, never merging; `isolation.require: false` is the only exception. Amendment 1: conventional run PR title |
| [ADR-018](ADR-018-no-nested-subagents.md) | No nested subagents | A step subagent starts no subagent; the orchestrator ignores a hand-back from a subagent it did not launch for the current step |
| [ADR-019](ADR-019-late-usage-figure.md) | Late usage figure | The `usage` command attaches a usage figure that reached the orchestrator after `next`, with guards, one commit in the archive state (restored on failure) and cut-off points in both skills |
| [ADR-020](ADR-020-ci-on-self-hosted-truenas-runners.md) | CI on self-hosted runners | CI runs on self-hosted TrueNAS runners with a hosted fallback for fork pull requests; the fork approval setting is the real boundary |
| [ADR-021](ADR-021-agent-smith-co-author.md) | Agent Smith co-author | Every router commit and the leftover commit of `open-pr.mjs` carry a `Co-Authored-By: Agent Smith` trailer from the policy key `coAuthor` (`null` turns it off) |
| [ADR-022](ADR-022-policy-validation-at-load.md) | Policy validation at load | The keys that cap spend and the prompt placeholders fail closed in `init`, `next` and `usage`; `status` reports `policyProblem`; `baseTier` may lie outside its bounds; `limits.maxNeutralRetries` is strict |
