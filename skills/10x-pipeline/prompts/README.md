# Pipeline prompts

Prompt templates for the optional pre-plan steps and the phase executors of `/agent-smith:10x-pipeline`, and the decision guides of the OpenSpec chain of `/agent-smith:openspec-pipeline` (ADR-013). `policy.json` refers to a file as `@prompts/<file>.md`, alone or as one part of an array prompt, and the router resolves the reference before it fills `{id}` (change id, or the OpenSpec change name), `{goal}` (goal text), `{verdict}` and, for the executor prompts, `{phase}`, `{lastPhase}`, `{retry}`, `{uncommitted}`, `{unproven}` and `{browserRows}` (phase numbers and row ids; `{unproven}` and `{browserRows}` read `none` when empty), `{lessonMax}` and `{lessonChars}` (the lesson candidate limits from `policy.json` `lessons`) and `{evidence}` (empty unless the retry could not check for a commit) and `{workdir}` (the run root of an isolated run, only in `worktree.md`) and `{findings}` (the `- ` lines under `## Critical` of the OpenSpec `verify.md`, or `see verify.md` when there are none, only in the `os-apply-fix` template), and appends `policy.json` `prompts.suffix`. The suffix carries the deletion rule of ADR-016 (never a recursive or forced delete; list, check, delete one by one, then `rmdir` deepest first), and `manual-verify.md` repeats it for its `mktemp -d` scratch directory. It also carries the nesting rule of ADR-018: a step subagent never calls the Agent or Task tool and never starts another subagent, because the report of a nested subagent goes to the top session; `executor-retry.md`, `executor-tdd.md`, `executor-e2e.md` and the `implement` and `implement-segment` templates repeat it in the words of the skill that delegates, and `research-with-map.md` asks for its three analyses one after the other in the step subagent. A file in this folder is either wired (a policy prompt refers to it) or listed under "Not wired".

Source: the 10xDevs 4.0 course prompts in `10xdevs4-content/.claude/prompts/`, in Polish. Each file was translated to English, shortened in caveman style with every negation, condition and number kept, and rewritten as rules in the form **GIVEN** context **WHEN** trigger **THEN** behavior, with one bold RFC 2119 keyword each (`MUST`, `MUST NOT`, `SHOULD`, `SHOULD NOT`, `MAY`). `frame-unattended.md`, `executor-e2e.md`, `executor-tdd.md`, `executor-retry.md`, `impl-review-warn.md`, `impl-review-lessons.md`, `plan-review-apply.md`, `impl-review-apply.md`, `plan-review-confirm.md`, `impl-review-confirm.md`, `manual-verify.md`, `score.md`, `worktree.md` and `advisor.md` are written for this pipeline and have no course source. The OpenSpec decision guides `os-propose.md`, `os-apply.md`, `os-verify.md` and `os-archive.md` are written for this pipeline too and have no course source.

A string or an array part that starts with `@prompts/` is a reference in every template, `archive` and `suffix` included, also in a project override: it is never literal text, and one that does not resolve halts the run at `init` or `next`. Literal text starts with any other character.

## Not wired

| File | Source | Why it is not wired |
| --- | --- | --- |
| `ast-grep-verification.md` | `m4l3-2-ast-grep-verification.md` | works on an existing `research.md`; stops as `blocked` when `ast-grep` is missing |
| `refactor-opportunities-research.md` | `m4l4-2-refactor-opportunities-research.md` | works on an existing `research.md`; it asks for three exploration subagents, which `prompts.suffix` forbids, so it needs the same rewrite as `research-with-map.md` before anyone wires it |
| `ranking-ast-grep-verification.md` | `m4l4-3-ranking-ast-grep-verification.md` | works on an existing `research.md`; stops as `blocked` when `ast-grep` is missing |

Changes from the source, so the prompts run unattended inside one change:

- Hardcoded change ids (`post-flow-analysis`, `refactor-opportunities`) and `{change-id}` became `{id}`. The fixed topic of `m4l3-1` (the post-saving flow) became `{goal}`.
- The domain briefs write to the change folder (`context/changes/{id}/refactor-*.md`), not to `context/domain/0N-*.md`, so a later change does not overwrite them and the router can verify them per change.
- The domain briefs prefer the invariant or leak that the change goal touches when two score close.
- Both ast-grep prompts stop with status `blocked` when `ast-grep` is not installed, instead of installing it.
