# Repository Guidelines

agent-smith is a Claude Code plugin that runs 10xDevs and OpenSpec skill chains. Each step runs in its own subagent, and a dependency-free Node.js ESM router picks the next step, model and effort. See @README.md for install and use, and @docs/REFERENCE.md for routing behavior.

## Hard Rules

- Keep routing decisions in `skills/10x-pipeline/scripts/route.mjs` and the modules it imports under `scripts/`, and in `skills/10x-pipeline/policy.json`. `SKILL.md` must not name models, effort levels or tiers beyond what it already documents, and `skills/openspec-pipeline/SKILL.md` names none beyond what `skills/10x-pipeline/SKILL.md` documents.
- `route.mjs` and the modules it imports under `scripts/` own `context/changes/<change-id>/agent-smith/run.jsonl` and `meta.json`, and for the OpenSpec chain `openspec/changes/<change-id>/agent-smith/run.jsonl` and `meta.json`. Never edit them by hand or from a skill.
- The router's only git writes are these (ADR-010). (1) The pre-archive commit in the `done` branch of a run started with `--archive`. (2) In an isolated run (`meta.isolated: true`), and only in its own linked worktree on `meta.branch`: the start commit of the first `init`, the commit of each successful step, the snapshot of a failed step under `refs/agent-smith/<id>/<run>/failed-<n>` (`<run>`: the first 12 hex characters of the run's start commit) (`git add -A`, `git write-tree`, `git commit-tree`, `git update-ref`), the `git reset --hard <startSha>` of its rollback, and the `git reset --hard <ref>` and `git reset -q <ref>^` that undo it on a halt. A failed commit runs a `git reset` of the router's own add. It never resets, commits in or writes refs from the main checkout, never pushes, never deletes a branch, worktree or ref, never passes `--no-verify` and sets no `-c` option except `core.quotePath=false`. Everything else it does with git is a read.
- The router never calls `gh`. `skills/10x-pipeline/scripts/pr-comment.mjs` is the only code that posts to GitHub, and only for a run started with `--pr-comment`. Its only network writes are one issue comment, created or edited, on an open `github.com` pull request of the current branch, found by a hidden marker. It never writes under the project root.
- Add no npm dependencies. The router uses only `node:` built-ins and must run on Node 24+ (ADR-006).
- Never edit `context/archive/`; it is read-only by convention.

## Project Structure

- `.claude-plugin/plugin.json` — plugin manifest. `.claude-plugin/marketplace.json` — marketplace listing this repo as its only plugin. Keep `name` and `description` aligned between the two and with @README.md. `version` is set only by the release PR (see Releases); `tools/version-check.mjs` fails when the fields differ.
- `skills/10x-pipeline/SKILL.md` — orchestrator instructions (the loop over router output).
- `skills/openspec-pipeline/SKILL.md` — orchestrator of the OpenSpec chain (ADR-013): the same loop for an OpenSpec change (`openspec/changes/<name>/`), calling the shared router at `../10x-pipeline/scripts/route.mjs` with `--chain openspec` on every call. Its `## Anti-stall rules` section equals the one of the 10x skill. It has no router, policy or prompts of its own.
- `skills/10x-pipeline/policy.json` — model ladder, base tiers, escalation, limits, prompt templates.
- `skills/10x-pipeline/baseline-policy.json` — per-project override that pins the baseline arm of `compare` (all tiers `sonnet`/`high`, `standard` rigor, no plan-review skip). Data the user copies; the router does not read it.
- `skills/10x-pipeline/scripts/route.mjs` — router: `init`, `next`, `status`, `risk`, `verify-archive`, `compare`.
- `skills/10x-pipeline/scripts/state.mjs`, `preplan.mjs`, `steps.mjs`, `openspec.mjs`, `flow.mjs`, `isolation.mjs` — the router modules `route.mjs` imports. Each imports only from the ones before it in this list, and none imports `route.mjs`, which runs `main()` on import. `state.mjs`: policy loading, plan and review readers, archive lookup, run log and `paths()`, rigor, churn, `halt`. `preplan.mjs`: pre-plan steps, complexity score, `replanNext`. `steps.mjs`: phase executors, manual verification, code re-plans, tier logic incl. `tierFor`. `openspec.mjs`: the OpenSpec chain (ADR-013), which reads `openspec/changes/<id>/` from files and never runs the `openspec` CLI: `readOpenspec`, the task row pattern (the CLI's), the guarded readers of `tasks.md` and `verify.md`, `readVerdict` of `verify.md`, the verification of the `os-` steps, `decideOpenspec` and the archive path. `flow.mjs`: report, result intake incl. `attachResult`, open findings and `decide`, prompts, agents and advisor. `isolation.mjs`: provenance, archive adapter, run isolation, step commits, rollback, `archiveDone`. `route.mjs` keeps `next`, the undo on halt and the commands.
- `skills/10x-pipeline/test/` — `node:test` suite: `route.test.mjs`, `churn.test.mjs`, `archive.test.mjs`, `rules.test.mjs`, `compare.test.mjs`, `lessons.test.mjs` (lesson candidates: sanitizer, report section, prompt wiring) and `helpers.mjs` (scratch projects, `run.jsonl` fixtures, hermetic git).
- `skills/10x-pipeline/prompts/` — rule-form prompt files; `policy.json` references them as `@prompts/<file>.md`.
- `skills/10x-pipeline/test/preplan.test.mjs`, `loops-existing.test.mjs` and `loops.test.mjs` — pre-plan gates and prompt wiring, the characterized RETHINK/REVISE loop (never edit it; the one exception is the two tier literals renumbered by ADR-010's ladder change), and the new loops and budget reference paths.
- `skills/10x-pipeline/test/executors.test.mjs`, `codereplan.test.mjs`, `manualverify.test.mjs`, `budget-executors.test.mjs` and `phase-helpers.mjs` — the phase-executors change: commit check, fallback, executor routing, retry, the report label (`executors.test.mjs`); code re-plans; `manual-verify` and `--chrome` (`manualverify.test.mjs`: every row in scope at every level, outside the pool, the tier and its retry, evidence kinds, the `evidence/unproven.md` reasons and their outputs, the prompt and the Chrome default); the budget derived from the longest legal path, `manual-verify` and its retry included, at `lean`, `standard` and `thorough` (`budget-executors.test.mjs`); and plan builders, log fixtures and `gateCheck` for the plan's Progress rows. `helpers.mjs` stays as it was, except for `writeOverride(project, policy)`: `makeProject` always writes the override file through it, and it adds `score: { minRigor: null }` unless the test gives its own `score` key, so existing tests keep `plan` as the first step, and `isolation: { require: false }` unless the test gives its own `isolation` key, so existing tests run in a plain scratch project, and `manualVerify: { minRigor: null }` unless the test gives its own `manualVerify` key, so existing tests keep their paths; a test turns the step on with `policy: { manualVerify: { minRigor: "lean" } }`.
- `skills/10x-pipeline/test/skill-loop.test.mjs` — content check of the `## Anti-stall rules` section of `SKILL.md`: five rules in order, placement outside the Loop branches, no model, effort or tier word. Its rule form is checked in `rules.test.mjs`.
- `skills/10x-pipeline/test/ladder.test.mjs`, `isolation.test.mjs`, `stepcommit.test.mjs`, `rollback.test.mjs` and `firstattempt.test.mjs` — the worktree-step-commits change (ADR-010): the 8-rung ladder and the effort floor on the rung's effort; the isolation gate of `init`; the start and step commits; the failed-step rollback and its undo on halt; the cheaper first implement attempt. The isolation, step-commit and rollback tests build real linked worktrees with hermetic git; a test turns isolation on with `policy: { isolation: { require: true } }`, because `writeOverride` adds `isolation: { require: false }` unless the test gives its own `isolation` key.
- `skills/10x-pipeline/test/openfindings.test.mjs` — routing of reviews on open findings (ADR-011): the parser of `### F<n>` blocks and `Decision` lines, the policy keys, the `review` field of the log entry and `status`, the plan and implementation review gates and their halt texts, the confirmation round and the `## Review findings` report section. It writes its own Decision-bearing reviews; `helpers.mjs` stays as it was, and its header-only `writeReview` keeps exercising the fallback.
- `skills/10x-pipeline/prompts/plan-review-confirm.md` and `impl-review-confirm.md` — rules of the opt-in confirmation review (`review.confirmRounds`), which re-checks the fixes an earlier round applied; `policy.json` wires them as the templates `plan-review-confirm` and `impl-review-confirm`; see `prompts/README.md`.
- `skills/10x-pipeline/prompts/worktree.md` — working-directory rules that open every prompt of an isolated run and name the run root; see `prompts/README.md`.
- `skills/10x-pipeline/test/score.test.mjs` — the complexity score step (ADR-007): policy data, gate, file validation, failure skip, tier shift, report and status. A test turns the scorer on with `policy: { score: { minRigor: "standard" } }`.
- `skills/10x-pipeline/test/provenance.test.mjs` — run provenance: the record in `meta.json`, hash stability, drift, legacy runs and the `compare` warnings. A test that changes a plugin file (a prompt, `plugin.json`, `agents/`) copies the plugin tree to a scratch directory, edits the copy and spawns the copy's `route.mjs`; it never edits a repository file.
- `skills/10x-pipeline/test/agents.test.mjs` — restricted step agents: the `agent` field of the run output, the log entry and `status`, malformed `agents` blocks, the agent definition file, the provenance link and the `SKILL.md` dispatch line. A test turns it on with `policy: { score: { minRigor: "standard" }, agents: { restricted: true } }`; a test that edits `agents/score.md` uses a scratch copy of the plugin tree.
- `skills/10x-pipeline/test/advisor.test.mjs` — the opt-in advisor (ADR-009): no advisor text with the default policy, its place in the prompts of the listed templates, the `advisor` log flag, malformed `advisor` blocks, the prompt file and the provenance link. A test turns it on with `policy: { advisor: { enabled: true } }`.
- `skills/10x-pipeline/prompts/advisor.md` — rules that ask `plan` and `implement` to consult the advisor once before the `RESULT` line; appended only when `advisor.enabled` is `true` (`advisor.templates` in `policy.json`). It names no model; see `prompts/README.md`.

- `skills/10x-pipeline/prompts/score.md` — rules and rubric of the `score` subagent, which writes `complexity.json`; see `prompts/README.md`.
- `skills/10x-pipeline/prompts/executor-e2e.md`, `executor-tdd.md`, `executor-retry.md`, `impl-review-warn.md` and `manual-verify.md` — prompts of the phase executors and `manual-verify`; see `prompts/README.md`.
- `skills/10x-pipeline/prompts/os-propose.md`, `os-apply.md`, `os-verify.md` and `os-archive.md` — decision guides of the OpenSpec steps, wired as the templates `os-propose`, `os-apply`, `os-apply-fix` (with `{findings}`), `os-verify` and `os-archive`; see `prompts/README.md`.
- `skills/10x-pipeline/test/openspec-helpers.mjs`, `openspec-chain.test.mjs`, `openspec-steps.test.mjs`, `openspec-isolation.test.mjs`, `openspec-archive.test.mjs`, `openspec-contract.test.mjs`, `openspec-readers.test.mjs` and `openspec-skill.test.mjs` — the OpenSpec chain (ADR-013): scratch OpenSpec projects built on `helpers.mjs`, which stays as it was; the `--chain` switch, run state, collisions and routing order; step verification, the `verify.md` verdict, the fix loop, tiers and dropped features; the start and step commits and the rollback of an isolated run; the archive branch and the read-only commands; the contract test against the real CLI (`OPENSPEC_BIN`, default `openspec`; it skips when the binary does not start); the content of `skills/openspec-pipeline/SKILL.md`.

- `release-please-config.json`, `.release-please-manifest.json` — release-please configuration and the current version. `.github/workflows/ci.yml` — tests, version check and commit lint; `.github/workflows/release.yml` — the release PR. See ADR-008.

## Commands

There is no build or lint setup. Run the tests with `node --test skills/10x-pipeline/test/*.test.mjs tools/test/*.test.mjs` (shell glob, Node 24 and later). Exercise the router from a project root that has `context/changes/<id>/change.md`, or, with `--chain openspec`, `openspec/changes/<id>/`. Every command takes `--chain 10x|openspec`; any other value halts before anything is read. Without the flag, `init` is a 10x init (it halts on a live OpenSpec run) and every other command uses the chain stored in `openspec/changes/<id>/agent-smith/meta.json` or in its archive folder; a `--chain` that contradicts the stored chain, or a live 10x run of the name, halts:

- `node skills/10x-pipeline/scripts/route.mjs init <id> --goal "<text>" [--rigor lean|standard|thorough] [--archive] [--chrome false] [--chain openspec]` — start or resume a run. With `--chain openspec` it halts, and writes nothing, when `openspec/changes/<id>/` is missing or `context/changes/<id>/` exists, and stores `chain: "openspec"` in `meta.json`; a 10x `meta.json` gets no `chain` key. `--archive` makes `done` commit the change folder and return an `archive` action (`--archive false` turns it off). The `manual-verify` template may use the Chrome tools by default; `--chrome false` picks the `manual-verify-nochrome` template, and `--chrome` or `--chrome true` changes nothing in effect.
- `node tools/version-check.mjs` — exit 0 when every version field is equal and valid SemVer. `node tools/commit-lint.mjs <range>` (for example `main..HEAD`) — exit 0 when every commit subject in the range is a Conventional Commit.
- `node skills/10x-pipeline/scripts/route.mjs next <id>` — consume `agent-smith/last-result.json`, return the next step.
- `node skills/10x-pipeline/scripts/route.mjs status <id> [--chain openspec]` — print the per-step model and effort log. An OpenSpec run adds `openspec: { planningComplete, tasks: { total, complete } }`.
- `node skills/10x-pipeline/scripts/route.mjs risk <id> [--chain openspec]` — print churn hot paths, plan hits and diff hits; writes nothing. An OpenSpec run has no plan, so it reports no plan hits.
- `node skills/10x-pipeline/scripts/pr-comment.mjs <id> [--report <p>]` — post the run report as a comment on the open pull request of the current branch, or edit its earlier comment. Prints one JSON object and exits 0 on a skip. Its tests are in `skills/10x-pipeline/test/pr-comment.test.mjs`; `GH_LIVE=1` enables the read-only live tests, which a human runs.
- `node skills/10x-pipeline/scripts/route.mjs verify-archive <id> [--path <p>] [--chain openspec]` — read-only; prints `archived: true` only when the archive folder has `status: archived` and `context/changes/<id>/` is gone. With `--chain openspec` it reads `openspec/changes/archive/` and prints `{ archived, path, report }`: an archive folder exists and `openspec/changes/<id>/` is gone, with no status stamp to read. Files only, no git.
- `node skills/10x-pipeline/scripts/route.mjs compare <id> --baseline <dir> [--routed <dir>] [--format md] [--unpinned] [--chain openspec]` — read-only; writes nothing. Compares the usage of a routed run with a baseline run (a second checkout with `baseline-policy.json` as its override) and prints totals, coverage, tokens by model and by tier, `comparable`, `reasons`, `warnings`, `dropPercent` and `verdict`. `--unpinned` is for the scorer A/B check: it accepts a baseline that is not pinned (a routed run with the scorer off), warns `baseline-unpinned` and gives the verdict `unpinned`; a value other than `true` or `false` halts.

## Coding Style

- Plain JavaScript ES modules, 2-space indent, double quotes, semicolons, as in `route.mjs`.
- Policy keys are camelCase; step names are kebab-case (`plan-review`, `impl-review`).
- A policy change belongs in `policy.json`. A per-project override belongs in `context/foundation/agent-smith-policy.json`, never in the router scripts under `scripts/`.
- When you change tier logic (`tierFor` in `scripts/steps.mjs`, `decide` in `scripts/flow.mjs`), update the "How the tier moves" list in `SKILL.md` and the routing bullets in `docs/REFERENCE.md`. When you change `decideOpenspec` or the verification in `scripts/openspec.mjs`, update the OpenSpec section of `docs/REFERENCE.md`.

## Testing

Run `node --test skills/10x-pipeline/test/*.test.mjs tools/test/*.test.mjs` after any change to `route.mjs` or a module it imports under `scripts/`, `policy.json`, a prompt or `tools/`. The suite drives the real router through the CLI in scratch projects and checks the rule form of every prompt. New router and test code must run on Node 24 (ADR-006). Then run `init` and `status` against a scratch change folder and confirm the JSON output is valid; for a change to the OpenSpec chain, also `init <id> --chain openspec --goal "<text>"` and `status <id> --chain openspec` in a scratch project with `openspec/config.yaml` and `openspec/changes/<id>/`.

## Commits

Every commit subject follows [Conventional Commits](https://www.conventionalcommits.org/): `type(scope)!: description`, with `type` one of `feat`, `fix`, `docs`, `chore`, `ci`, `refactor`, `perf`, `test`, `build`, `revert`. The `commits` job in `ci.yml` checks each commit of a pull request, because the owner rebase-merges and the subjects land on `main`. The type sets the SemVer bump (ADR-008):

| Commit | Bump |
| --- | --- |
| `feat:` | minor |
| `!` after the type, or a `BREAKING CHANGE:` footer | minor while the version is below 1.0.0, major from 1.0.0 |
| any other type | patch (release-please's default when a release has no `feat` or breaking commit) |

Whether a commit opens a release PR on its own depends on release-please's changelog sections: by default `docs`, `chore`, `refactor`, `test`, `build` and `ci` are hidden, `feat`, `fix`, `perf` and `revert` are shown. That part is not tested here; the first release PR confirms it.
Add a `Co-Authored-By:` trailer for AI-assisted commits.

## Releases

Releases are made by [release-please](https://github.com/googleapis/release-please) in the release-PR model (`.github/workflows/release.yml`, `release-please-config.json`, `.release-please-manifest.json`; ADR-008). Every push to `main` updates one release PR. Merging it sets the version, creates the tag `vX.Y.Z` and publishes a GitHub Release with the changelog (`CHANGELOG.md`).

- **One version, four fields.** `plugin.json` `version`, `marketplace.json` `metadata.version` and `plugins[0].version`, and the manifest `.` hold the same version. release-please updates them together; never edit them by hand. `tools/version-check.mjs` runs in `ci.yml` and fails on drift.
- **Owner setting, once.** Settings → Actions → General → "Allow GitHub Actions to create and approve pull requests". Without it `release.yml` fails when it opens the PR.
- **No checks on the release PR.** A PR opened with `GITHUB_TOKEN` starts no other workflow. `main` has no required checks, so the owner merges it after reading the diff.
- **Version line.** The version is `0.x` (SemVer initial development). To release `1.0.0`, put a `Release-As: 1.0.0` footer on a commit.
- **Release type.** A run of only hidden-section commits (`docs`, `chore`, `ci`, `test`, `build`, `refactor`) is expected to open no release PR; the next `feat` or `fix` does.
