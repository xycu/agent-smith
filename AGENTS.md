# Repository Guidelines

agent-smith is a Claude Code plugin that runs 10xDevs and OpenSpec skill chains. Each step runs in its own subagent, and a dependency-free Node.js ESM router picks the next step, model and effort. See [README.md](README.md) for install and use, and [docs/REFERENCE.md](docs/REFERENCE.md) for routing behavior (read them only when the task needs them).

## Hard Rules

- Keep routing decisions in `skills/10x-pipeline/scripts/route.mjs` and the modules it imports under `scripts/`, and in `skills/10x-pipeline/policy.json`. `SKILL.md` must not name models, effort levels or tiers beyond what it already documents, and `skills/openspec-pipeline/SKILL.md` names none beyond what `skills/10x-pipeline/SKILL.md` documents.
- `route.mjs` and the modules it imports under `scripts/` own `context/changes/<change-id>/agent-smith/run.jsonl` and `meta.json`, and for the OpenSpec chain `openspec/changes/<change-id>/agent-smith/run.jsonl` and `meta.json`. Never edit them by hand or from a skill.
- Git and GitHub: only operations that cannot be undone are forbidden. Code, skills and prompts may commit, branch, add worktrees, write refs, push a branch and create, edit or comment on pull requests and issues. They never: force-push or rewrite pushed history; delete a branch, tag, ref or worktree that holds commits reachable from nowhere else; discard uncommitted work that no commit or ref holds (`git reset --hard`, `git checkout -- <path>`, `git clean`, `git stash drop` or `clear`); pass `--no-verify`; delete a repository, release, tag, issue or comment on GitHub, or change repository settings or branch protection. The router's current git writes and their recovery paths are in ADR-010 (the rollback snapshots the worktree under `refs/agent-smith/` before its `git reset --hard`), and the one commit of the `usage` command for a run in the archive state is in ADR-019; `skills/10x-pipeline/scripts/pr-comment.mjs` posts the run report and `skills/10x-pipeline/scripts/open-pr.mjs` pushes the run branch and opens its pull request at every end of a run, never with force and never merging (ADR-017; see Commands). The router never pushes and never calls `gh`.
- Add no npm dependencies. The router uses only `node:` built-ins and must run on Node 24+ (ADR-006).
- Never delete a directory tree with a recursive or forced command (`rm -rf`, `rm -r`, `rimraf`, `find -delete`, `fs.rm`/`fs.rmSync`/`fs.rmdir` with `recursive: true`) in code, tests, skills, prompts or docs. List the files, check the list, delete them one by one, then `rmdir` the empty directories deepest first. Code and tests use `removeTree` from `skills/10x-pipeline/scripts/remove-tree.mjs`; `skills/10x-pipeline/test/no-recursive-delete.test.mjs` guards the ban (ADR-016).
- Never edit `context/archive/`; it is read-only by convention.

## Commands

There is no build or lint setup. Run the tests with `node --test skills/10x-pipeline/test/*.test.mjs tools/test/*.test.mjs` (shell glob, Node 24 and later). Exercise the router from a project root that has `context/changes/<id>/change.md`, or, with `--chain openspec`, `openspec/changes/<id>/`. Every command takes `--chain 10x|openspec`; any other value halts before anything is read. Without the flag, `init` is a 10x init (it halts on a live OpenSpec run) and every other command uses the chain stored in `openspec/changes/<id>/agent-smith/meta.json` or in its archive folder; a `--chain` that contradicts the stored chain, or a live 10x run of the name, halts:

- `node skills/10x-pipeline/scripts/route.mjs init <id> --goal "<text>" [--rigor lean|standard|thorough] [--archive] [--chrome false] [--chain openspec]` — start or resume a run. With `--chain openspec` it halts, and writes nothing, when `openspec/changes/<id>/` is missing or `context/changes/<id>/` exists, and stores `chain: "openspec"` in `meta.json`; a 10x `meta.json` gets no `chain` key. `--archive` makes `done` commit the change folder and return an `archive` action (`--archive false` turns it off). The `manual-verify` template may use the Chrome tools by default; `--chrome false` picks the `manual-verify-nochrome` template, and `--chrome` or `--chrome true` changes nothing in effect.
- `node tools/version-check.mjs` — exit 0 when every version field is equal and valid SemVer. `node tools/commit-lint.mjs <range>` (for example `main..HEAD`) — exit 0 when every commit subject in the range is a Conventional Commit.
- `node skills/10x-pipeline/scripts/route.mjs next <id>` — consume `agent-smith/last-result.json`, return the next step.
- `node skills/10x-pipeline/scripts/route.mjs status <id> [--chain openspec]` — print the per-step model and effort log. An OpenSpec run adds `openspec: { planningComplete, tasks: { total, complete } }`.
- `node skills/10x-pipeline/scripts/route.mjs risk <id> [--chain openspec]` — print churn hot paths, plan hits and diff hits; writes nothing. An OpenSpec run has no plan, so it reports no plan hits.
- `node skills/10x-pipeline/scripts/route.mjs usage <id> <n> --tokens N [--tool-uses N] [--duration-ms N] [--chain 10x|openspec]` — attach a usage figure that reached the orchestrator after `next` to executed step `<n>` (ADR-019). Prints `{ action: "usage", attached, n, step, usage, unchanged, report, commit }`, or `attached: false` with a `reason` and exit 1, and then writes nothing. A figure is never overwritten. It rewrites `report.md` of an ended run. For an ended `--archive` run it commits the change folder as `archive.usageMessage` (`chore(<id>): add late usage figure of step <n>`) and restores the old bytes when that fails before the commit exists; this is its only git write.
- `node skills/10x-pipeline/scripts/open-pr.mjs <id> [--chain 10x|openspec] [--report <p>] [--remote <name>] [--base <branch>] [--draft] [--timeout-ms <n>]` — from the run root of an isolated run: commit leftovers, push the run branch without force, open or keep its pull request (ADR-017). Prints one JSON object, exits 0 on every runtime outcome and 2 on a usage error.
- `node skills/10x-pipeline/scripts/pr-comment.mjs <id> [--report <p>] [--pr <url>]` — post the run report as a comment on the pull request `--pr` names, else on the open pull request of the current branch, or edit its earlier comment. Prints one JSON object and exits 0 on a skip. Its tests are in `skills/10x-pipeline/test/pr-comment.test.mjs`; `GH_LIVE=1` enables the read-only live tests, which a human runs.
- `node skills/10x-pipeline/scripts/route.mjs verify-archive <id> [--path <p>] [--chain openspec]` — read-only; prints `archived: true` only when the archive folder has `status: archived` and `context/changes/<id>/` is gone. With `--chain openspec` it reads `openspec/changes/archive/` and prints `{ archived, path, report }`: an archive folder exists and `openspec/changes/<id>/` is gone, with no status stamp to read. Files only, no git.
- `node skills/10x-pipeline/scripts/route.mjs compare <id> --baseline <dir> [--routed <dir>] [--format md] [--unpinned] [--chain openspec]` — read-only; writes nothing. Compares the usage of a routed run with a baseline run (a second checkout with `baseline-policy.json` as its override) and prints totals, coverage, tokens by model and by tier, `comparable`, `reasons`, `warnings`, `dropPercent` and `verdict`. `--unpinned` is for the scorer A/B check: it accepts a baseline that is not pinned (a routed run with the scorer off), warns `baseline-unpinned` and gives the verdict `unpinned`; a value other than `true` or `false` halts.

## Coding Style

- Plain JavaScript ES modules, 2-space indent, double quotes, semicolons, as in `route.mjs`.
- Policy keys are camelCase; step names are kebab-case (`plan-review`, `impl-review`).
- A policy change belongs in `policy.json`. A per-project override belongs in `context/foundation/agent-smith-policy.json`, never in the router scripts under `scripts/`.
- When you change tier logic (`tierFor` in `scripts/steps.mjs`, `decide` in `scripts/flow.mjs`), update the "How the tier moves" list in `SKILL.md` and the routing bullets in `docs/REFERENCE.md`. When you change `decideOpenspec` or the verification in `scripts/openspec.mjs`, update the OpenSpec section of `docs/REFERENCE.md`.

## Testing

Run `node --test skills/10x-pipeline/test/*.test.mjs tools/test/*.test.mjs` after any change to `route.mjs` or a module it imports under `scripts/`, `policy.json`, a prompt or `tools/`. The suite drives the real router through the CLI in scratch projects and checks the rule form of every prompt. New router and test code must run on Node 24 (ADR-006). Then run `init` and `status` against a scratch change folder and confirm the JSON output is valid; for a change to the OpenSpec chain, also `init <id> --chain openspec --goal "<text>"` and `status <id> --chain openspec` in a scratch project with `openspec/config.yaml` and `openspec/changes/<id>/`.

## Commits

Every commit subject follows [Conventional Commits](https://www.conventionalcommits.org/): `type(scope)!: description`, with `type` one of `feat`, `fix`, `docs`, `chore`, `ci`, `refactor`, `perf`, `test`, `build`, `revert`. The `commits` job in `ci.yml` checks each commit of a pull request, because the owner rebase-merges and the subjects land on `main`. The type sets the SemVer bump (ADR-008):

| Commit | Bump |
| --- | --- |
| `feat:` | minor |
| `!` after the type, or a `BREAKING CHANGE:` footer | minor while the version is below 1.0.0, major from 1.0.0 |
| any other type | patch (release-please's default when a release has no `feat` or breaking commit) |

Whether a commit opens a release PR on its own depends on release-please's changelog sections: by default `docs`, `chore`, `refactor`, `test`, `build` and `ci` are hidden, `feat`, `fix`, `perf` and `revert` are shown. That part is not tested here; the first release PR confirms it.

## Releases

Releases are made by [release-please](https://github.com/googleapis/release-please) in the release-PR model (`.github/workflows/release.yml`, `release-please-config.json`, `.release-please-manifest.json`; ADR-008). Every push to `main` updates one release PR. Merging it sets the version, creates the tag `vX.Y.Z` and publishes a GitHub Release with the changelog (`CHANGELOG.md`).

- **One version, four fields.** `plugin.json` `version`, `marketplace.json` `metadata.version` and `plugins[0].version`, and the manifest `.` hold the same version. release-please updates them together; never edit them by hand. `tools/version-check.mjs` runs in `ci.yml` and fails on drift.
- **Owner setting, once.** Settings → Actions → General → "Allow GitHub Actions to create and approve pull requests". Without it `release.yml` fails when it opens the PR.
- **No checks on the release PR.** A PR opened with `GITHUB_TOKEN` starts no other workflow. `main` has no required checks, so the owner merges it after reading the diff.
- **Version line.** The version is `0.x` (SemVer initial development). To release `1.0.0`, put a `Release-As: 1.0.0` footer on a commit.
- **Release type.** A run of only hidden-section commits (`docs`, `chore`, `ci`, `test`, `build`, `refactor`) is expected to open no release PR; the next `feat` or `fix` does.
