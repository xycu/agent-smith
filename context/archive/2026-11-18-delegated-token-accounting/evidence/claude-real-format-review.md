# Claude Code 2.1.311 native capture compatibility check

A fresh headless fixture ran a foreground Agent step that delegated once. It captured exact PreToolUse, PostToolUse and SubagentStop records through process-local command hooks, byte-for-byte temporary copies of the two agent transcripts, and one process's OTLP HTTP JSON event batches on loopback. The disposable launcher provided process PID and creation time via OTLP resource attributes. No existing settings or export destinations were changed. The originating process's six distinct requests added to the final whole-query modelUsage of 28,607 tokens. An independently matched four-request step subtree added to 13,209 tokens, excluding two main-session requests. The two native Agent totals (2,671 and 4,602) reflected only their final requests. Only five of six whole-query requests had arrived at the final result.

The initial Phase 3 collector returned unavailable for this complete captured source. The replay found three pinned-format differences:

1. The installed HTTP JSON exporter emits integer-valued fields such as event.sequence as JSON numbers in intValue. Accept validated nonnegative safe integers in both numeric and decimal-string encodings.
2. assistant_response identifies text-bearing messages. Each agent emitted it for its last response only, while each agent had two api_request events and two independently matching transcript request IDs. Compare the full bidirectional set of transcript and telemetry requests and their counters. Validate any assistant_response against transcript UUID and request ID and require the actual terminal response. Do not require assistant_response on tool-use-only requests.
3. The version's transcript includes UUID-linked attachment messages between user and assistant records. Some earlier attachments are physically serialized out of parent order. Prove the unique parent path from the final assistant to the first launch user, accepting recognized UUID-linked attachment nodes without reading their contents. Reject broken, disconnected, or cyclic history. Keep matching the final SubagentStop text and exact request set; the observed first prompt and last text both matched.

With only those adaptations, a scratch copy of the collector recovered all 13,209 tokens over two agents and four requests. Removing the first descendant api_request while preserving its terminal records yielded unavailable/incomplete-capture with no total. The scratch copy was not applied to the repository. Cover these observed host formats with sanitized fixtures. Revalidate exact membership and preserve the existing unavailable result for missing exporter provenance, missing transcript, or incomplete prefix. This retained-record replay covers one native headless configuration and does not qualify every planned host or pipeline mode. No raw records, local paths, credentials, or identifiers are included here.

A second process-qualified headless run used an OpenSpec-style `os-apply` launch identity. The scratch adapter was called synchronously from the enclosing PostToolUse hook and returned unavailable/incomplete-capture with no total. After the exporter naturally drained, the same invocation reconciled 13,374 subtree tokens across four requests. The independently measured whole query reconciled 28,713 over six requests. This proves the collector timing behavior for one native configuration. It did not run an OpenSpec proposal/apply/verify workflow or exercise GitHub publication.
