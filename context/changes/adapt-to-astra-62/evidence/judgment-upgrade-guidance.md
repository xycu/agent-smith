# Manual 1.3 — Upgrade guidance

- **Adoption and override keys.** The upgrade note says “Installing the plugin does not rewrite copied overrides” and directs users to “explicitly re-merge the entire preset ladder … preserving unrelated keys and reconciling any custom ladder.” README.md says “Existing overrides need a deliberate merge because arrays replace whole.” The policy loader in `state.mjs` replaces arrays as a unit, so applying only the new ladder preserves other project override keys. [Upgrade note](../../../../docs/REFERENCE.md#codex-and-provider-dispatch) · [README](../../../../README.md)
- **Historical and new targets.** The note says “Recorded attempts and pending/neutral retries retain their stored targets, while newly selected targets use the effective ladder.” Both chains' neutral-rerun tests change the ladder after a dispatch and verify that the replay keeps its original model and effort. New dispatches call `dispatchTarget(policy, tier)` in `route.mjs`. [Test output](test-upgrade-behavior.txt)
- **Drift and comparisons.** The note says “A ladder change during a run records `provenance.drift` and a separate drift warning; merely installing an unused preset does not. Between runs, `ladder` is an allowed difference in default pinned comparison mode.” The reference's Run provenance section confirms that `next` rehashes merged sections against the original record. The tests verify that drift preserves the original hashes, and that the pinned section exemption suppresses a between-run ladder warning while recorded drift is reported independently. [Reference](../../../../docs/REFERENCE.md) · [Test output](test-upgrade-behavior.txt)
- **Rollback.** The note directs maintainers to “restore the prior seven model values in both repository policies with the matching assertion and upgrade guidance through a preserving forward edit or revert” and says “downstream users can re-merge their prior ladder while preserving other keys.” This reverses the effective selection for future dispatches, subject to the older models being available. The note says “Rollback affects later dispatches and can itself record drift” and directs readers to preserve recorded targets and logs. [Reference](../../../../docs/REFERENCE.md)
