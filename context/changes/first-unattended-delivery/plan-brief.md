## What & Why

S-12 establishes the first complete Claude-only plan-based delivery through an installed pipeline to a reviewable PR. Existing implementation supplies the execution path. This change prepares reproducible acceptance and repairs failures supported by observed evidence.

## Starting Point

Isolation, routing, guarded steps, result handling, commits and publication are implemented. Fresh-host guard enforcement and complete unattended Claude delivery remain unproved. The current Codex run uses an OpenAI ladder.

## Desired End State

One fresh Claude-only headless run finishes its authorized documentation change without steering and publishes the completed head for review. Evidence identifies exact versions, configuration, invocation ownership, terminal outcome and residual work.

## Scope

S-12 covers launch specification, local proof, installed discovery/guard evidence and one complete delivery. S-15 through S-20 retain broader diagnostics, recovery, protection and final qualification. The quoting change retains its owner-directed gate.

## Architecture / Approach

Reuse existing provider, setup, step-commit, loop, guard and publication fixtures. Prepare Markdown evidence under this change. A separate acceptance project uses committed candidate defaults for Claude routing before isolation. Its normal pipeline owns execution and publication.

## Phases at a Glance

| Phase | Deliverable | Key risk |
| --- | --- | --- |
| 1. Define the Acceptance Launch | Launch contract and attempt checklist | Effective installed configuration differs from source |
| 2. Verify the Local Delivery Contracts | Focused/full test evidence and reproduced fixes | Fixture scope overstates native host behavior |
| 3. Accept the Fresh Claude Delivery | Native discovery/guard proof and completed run PR | Trust, quota, permissions or publication blocks launch/completion |

Prerequisites include Node 24+, Claude Code 2.1.295+ for guard proof, pinned candidate/toolkit discovery, trusted acceptance project and authenticated model/review-remote access. Exact versions are measured before each live attempt.

Estimated effort is one local preparation/verification pass and one complete live acceptance attempt, followed by failure-driven repairs and fresh attempts when needed.

## Open Risks & Assumptions

- Workload selection assumes documentation delivery qualifies S-12. Its scope follows the roadmap outcome of authorized completed work on a PR.
- Runtime versions, quota, trust and installed discovery remain execution prerequisites to measure. Historical versions establish earlier observations.
- The current Codex run retains its policy and saved identity. Claude acceptance uses a separate fresh project beneath this run root.
- Phase 3 stays Manual through local implementation. The acceptance top-level orchestrator owns live publication and retains all attempts and interventions.
- Unresolved execution ownership follows existing settlement and router recovery. Evidence preserves its candidate and TMPDIR.

## Success Criteria (Summary)

- Automated local readiness includes the launch/evidence contract, focused tests, full suite and version consistency.
- Manual acceptance proves fresh guarded Claude execution and one complete normal-entry delivery with zero post-launch steering.
- Manual publication acceptance matches the actual completed head and artifacts to a reviewable PR, recording CI and residual worktree state.
