# Research: Token accounting for delegated pipeline steps

**Date** 2026-11-18, Europe/Warsaw  
**Researcher** Codex  
**Git commit** `ca97aaefb095919a9467776f1016b1ca64ba355c`, detached HEAD  
**Repository** `agent-smith`

## Research Question

How do OpenAI Codex and Anthropic Claude Code recommend measuring token usage for a step and its children? Which sources can Agent Smith use while preserving the native execution and settlement guarantees of both pipeline entry points? [Change scope](change.md)

## Summary

- **Codex:** `exec --json` in the installed `0.169.0` filters usage to the primary thread and turn. Keep the existing executor. For that version, the strongest local candidate is to read attributed response usage records from the already settled parent and descendants. The public protocol exposes identities, settlement and live usage notifications, while its inspected read responses carry no historical token total. The local rollout path is explicitly unstable. [Exec source](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/exec/src/lib.rs#L1752-L1802) · [App Server](https://developers.openai.com/codex/app-server) · [Pinned thread schema](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/app-server-protocol/src/protocol/v2/thread_data.rs#L210-L270)
- **Claude Code:** Anthropic defines foreground Agent `totalTokens` and the `subagent_completed` event as final-request counts. The retained `2.1.311` headless probe showed the same count in the step’s `<usage>` block and structured notification. A flat step that makes several requests can also undercount through that path. For the existing native Agent flow, use opt-in per-request telemetry as the supported candidate and qualify its completeness. For an isolated Agent SDK query, `modelUsage` is the documented whole-query total. [Agent hook fields](https://code.claude.com/docs/en/hooks#agent) · [Completion event](https://code.claude.com/docs/en/monitoring-usage#subagent-completed-event) · [SDK cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking#get-the-total-cost-of-a-query) · [Retained probe analysis](#claude-code)

## Detailed Findings

### Codex

**Documented surface.** OpenAI documents JSONL output for `codex exec --json`. In the pinned source, both token notifications and completion are filtered on the primary thread and turn. Completion emits the latest cumulative `total` snapshot, with default zero values if no snapshot was received. Treat a zero without separate usage evidence as ambiguous. Use the existing `thread/list` ancestor traversal and completed-turn metadata to establish the exact thread set. The generated `0.169.0` `ThreadReadResponse` and `ThreadTurnsListResponse` were inspected locally. Their thread/turn shapes have no token snapshot field. The host's `thread/tokenUsage/updated` notification supplies `threadId`, `turnId`, `total` and `last`; it is documented for the active thread. [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode#structured-output) · [Pinned exec completion](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/exec/src/event_processor_with_jsonl_output.rs#L512-L538) · [App Server](https://developers.openai.com/codex/app-server) · [Notification type](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/app-server-protocol/src/protocol/v2/thread.rs#L2104-L2159)

**Historical reads.** Codex source and tests show that `thread/resume` can replay a cumulative snapshot for retained histories. For example, the test includes turns and checks both the thread and turn IDs; a separate test shows that excluding turns skips replay. Resuming loads execution state and may hydrate history, so this is evidence for the snapshot semantics, not the recommended production collection mechanism. `account/usage/read` supports an optional thread ID in `0.169.0`, but its thread result is a billing-route-dependent estimate and the documented account endpoint is ChatGPT-specific. [Resume replay tests](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/app-server/tests/suite/v2/thread_resume.rs#L4223-L4269) · [Replay implementation](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/app-server/src/request_processors/token_usage_replay.rs#L28-L67) · [Account usage schema](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/app-server-protocol/src/protocol/v2/account.rs#L467-L484) · [Account usage docs](https://learn.chatgpt.com/docs/app-server#7-token-usage-chatgpt)

**Recommended candidate.** Have the existing settlement observer supply verified thread IDs, causal turn IDs and available host-reported paths. For supported local rollouts, a version-gated, bounded read-only reader can sum `token_usage_record.usage` once per distinct `(thread_id, response_id)` with matching root session and root turn. A child's `session_id` can identify the enclosing session, so use its actual `thread_id` for child identity. Include attributable, provider-reported usage from incomplete responses where the pinned host records it. Reject foreign or conflicting records and unknown causality. A missing rollout or unsupported shape keeps the total unavailable. Validate canonical paths and file identity before reading, and retain derived counters and coverage reasons in Agent Smith state. Prefer response records to arbitrary cumulative snapshots, which can describe different scopes or include context-window estimates. No host API inspected here contracts for a general read-only settled-tree total. [Runner settlement](../../../skills/10x-pipeline/scripts/run-codex.mjs#L181) · [Record schema](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/protocol/src/protocol.rs#L2566-L2577) · [Recording and causal IDs](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/core/src/session/mod.rs#L5631-L5719) · [Context snapshot behavior](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/protocol/src/protocol.rs#L2617-L2648)

**Observed run.** A read-only recheck of the identified PR #214 records found 285 distinct response IDs across six numbered step sessions, five child sessions and one archive session. Per-session response sums agreed with the final snapshots. The five children contributed 4,188,412 tokens. The six numbered steps totaled 29,027,825 tokens including cached input, and archive added 826,666. This corroborates the reconstruction for that run. The upstream tests show that a response without reported usage produces no usage record, so this measures observed usage within the matched execution and cannot certify billing completeness. [PR reconstruction](https://github.com/xycu/agent-smith/pull/214#issuecomment-6935363565) · [Pinned usage-record test](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/core/tests/suite/token_usage_rollout.rs#L43-L113)

### Claude Code

**Native Agent usage.** Anthropic’s hook reference says foreground `tool_response.totalTokens` and `usage` cover the final API request. The background launch response returns without usage. The `subagent_completed.total_tokens` event is also final-request scoped. `SubagentStop` supplies `agent_id` and its transcript path, and can fire for internal agents. The transcript's JSONL entry format is explicitly internal and version-dependent. Use hook and task identities to match launches, with `run_id` when available to distinguish resumes and late deliveries. Identity, time and tool-use measurements cannot establish token coverage by themselves. [Agent hook fields](https://code.claude.com/docs/en/hooks#agent) · [SubagentStop](https://code.claude.com/docs/en/hooks#subagentstop-input) · [Transcript format](https://code.claude.com/docs/en/sessions#where-transcripts-are-stored) · [SDK task identity](https://code.claude.com/docs/en/agent-sdk/typescript#sdktaskstartedmessage)

**Observed probe.** In the retained `2.1.311` headless fixture, the step's foreground tool response, structured terminal task notification, and text `<usage>` block each displayed 612,798 tokens. That equals the step's last request. Independent transcript grouping by assistant message ID counted two distinct requests each for the step and child, totaling 1,219,870 and 1,213,070 tokens respectively across uncached input, output, cache read and cache creation. The step and child together used 2,432,940 in this probe. Adding the orchestrator's 1,209,548 matched the final `modelUsage` sum of 3,642,488. Thus the whole-query figure would include unrelated orchestrator usage if attached to that native step. The raw fixture is `claude-headless-events.jsonl` in the archived evidence's retained probe directory, with identities on lines 23 and 29, notifications and hand-backs on lines 35–42, and the result on line 52. [Probe provenance](../../archive/2026-11-16-nested-step-delegation/evidence/capabilities.md#claude-headless)

**Recommended native candidate.** Anthropic documents optional `claude_code.api_request` events with uncached input, cache reads, cache creation and output. Event attributes `agent_id` and `parent_agent_id` are documented from `2.1.310`, within the inspected `2.1.311` baseline. Match the recorded Agent invocation to its session and descend through verified parent/child IDs, then count each distinct API request once. Require a bounded, complete capture for that invocation, including late delivery, retries, resumed agents and auxiliary calls where applicable. A task finishing does not prove the export has flushed. The token counter grouped by agent type or `query_source` is useful for aggregate monitoring and cannot recover exact invocation boundaries from the documented metric attributes. Repository settings cannot enable or redirect export. Prototype using existing operator-authorized telemetry or an explicitly configured local capture, with prompts and tool details out of scope. [Exporter configuration](https://code.claude.com/docs/en/monitoring-usage) · [Event attributes](https://code.claude.com/docs/en/monitoring-usage#standard-attributes) · [Request identities](https://code.claude.com/docs/en/monitoring-usage#event-correlation-attributes) · [API request event](https://code.claude.com/docs/en/monitoring-usage#api-request-event)

**Independent check and alternative boundary.** The Agent SDK defines `modelUsage` as cumulative by model across the query pipeline, including subagents and compaction, with helpers outside that pipeline excluded. For a fresh isolated query it is a useful verification reference. For resumed or streaming queries, take the final snapshot within the correct boundary or a verified delta against the starting snapshot. The `usage` result field measures the main loop. An SDK query per Agent Smith step could supply its own whole-query total but would change how Claude dispatches, applies guards and settles children; that option needs separate design evidence if native telemetry is insufficient. [SDK fields](https://code.claude.com/docs/en/agent-sdk/typescript#sdkresultmessage) · [SDK cost and resume](https://code.claude.com/docs/en/agent-sdk/cost-tracking)

## Architecture Insights

- Keep the meaning of `usage.totalTokens` consistent for a reported step. Use host-owned measurement and identity matching, count cumulative snapshots once, and avoid adding cache or reasoning subsets twice. In the inspected Codex records, total matched input plus output with cached input already included. Claude request events define uncached input separately, so add cache read and cache creation once. A complete observed total is distinct from billing data. [Codex usage handling](../../../skills/10x-pipeline/scripts/run-codex.mjs#L244) · [Claude request definitions](https://code.claude.com/docs/en/monitoring-usage#api-request-event)
- Separate token collection failure from closure, result verification and rollback. Preserve a missing total with a reason when usage is absent, ambiguous, conflicting, truncated or outside proven coverage. Keep the known duration and tool-use scope. Share the Codex collector through the runner and keep Claude's immediate, late and archive rules aligned across both skills. The existing late `usage` command treats an existing usage object as immutable, even if it contains duration alone. Late enrichment would need an explicit, narrowly tested contract that cannot overwrite existing figures or match a newer retry. [Runner intake](../../../skills/10x-pipeline/scripts/run-codex.mjs#L394) · [10x late usage](../../../skills/10x-pipeline/SKILL.md#late-usage-before-every-end) · [OpenSpec late usage](../../../skills/openspec-pipeline/SKILL.md#late-usage-before-every-end) · [Router usage command](../../../skills/10x-pipeline/scripts/route.mjs#L764)
- The existing report and comparison read the step scalar. Their provider/model grouping and optional blended estimate use the enclosing step's routing model. A subtree with mixed child models makes that estimate a routing-rate approximation. The plan should label or suppress that estimate where needed before treating it as model-specific spend. Keep archive-only measurements outside numbered-step totals and archived ledgers outside this change. [Report rendering](../../../skills/10x-pipeline/scripts/flow.mjs#L111) · [Cost estimator](../../../skills/10x-pipeline/scripts/state.mjs#L214) · [Compare grouping](../../../skills/10x-pipeline/scripts/route.mjs#L446)

## Open Questions and Planning Handoff

- **Codex:** Qualify the pinned reader on a new delegated run, including a child that makes several requests, duplicate or late records, missing usage, archived descendants, outside-path records, and resumed or forked history. Establish how the supported rollout format signals an incomplete capture, beyond agreement between two counters derived from the same records. Fail closed on usage if the host changes schema, lineage or local storage capabilities.
- **Claude Code:** Run a bounded multiple-request native Agent probe in headless and interactive modes, exercising immediate, late and archive accounting. Compare per-request totals with a fresh isolated `modelUsage` reference. Verify exporter completion and request/agent identity under retries, resumes, background delivery and incomplete capture. Confirm whether flat-step notification accounting also needs migration for the intended supported versions. An operator telemetry prerequisite or a different execution boundary is a product decision if the native contract cannot supply dependable coverage.
- **Shared proof:** Use sanitized fixtures for valid, duplicate, mixed, partial and mismatched token records through both pipeline entry points. Verify exactly one result intake, no settlement or permission change caused by token reads, and a visible omission reason where coverage is incomplete. Compare rollout-derived and native metrics at the same invocation boundary and preserve the recorded scope of legacy totals. No new model sessions or repository tests ran in this documentation investigation.

## Recovery evidence and delivery decision

The initial plan stopped because historical totals alone did not prove capture completeness. Treat the following checks as the resolution of the planning decision, while retaining the open questions above as implementation and verification cases. The scope remains delivery for both hosts with an honest unavailable state when a particular host or invocation cannot prove coverage.

- **Codex negative control.** In one retained `0.169.0` child session from PR #214, the sum of seven per-response usage records was 682,767, equal to the final `TokenCount` snapshot for the completed turn. Removing the first response record from the in-memory fixture caused the sum to disagree with that snapshot. The inspected rollout contained no persisted `raw_response_completed` event. Use the separate cumulative snapshot as a consistency check on the observed records for fresh, attributable threads. It detects the tested missing-record case. A response omitted by upstream telemetry can be absent from both sources, so the contract is verified *observed* host usage, with the billing limit stated. Failed joins, unsupported versions, conflicting snapshots, and ambiguous inherited history leave usage unavailable without blocking result intake. [Pinned source: response usage and absent usage](https://github.com/openai/codex/blob/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/core/src/session/mod.rs#L5698-L5719)
- **Claude positive and timing controls.** On Claude Code `2.1.311`, a fresh read-only headless Haiku query with one foreground leaf exported four distinct attributable API request records, split two and two between the root and leaf. Its four token buckets summed to 30,842, exactly the final isolated `modelUsage` reference. A second query with an enclosing step and nested leaf exported six distinct API request records, two each for the orchestrator, step and leaf. The leaf’s `parent_agent_id` matched the step in two request records. The collector had three requests at the first task notification, four at the second, and five when it observed the final result. After normal process close and the local collector drain, six records summed to 44,387, exactly the final isolated `modelUsage` reference. Both runs returned the expected nonce and exited zero. Sanitized probe summaries are in `/private/tmp/agent-smith-claude-token-probe-4ylToP/summary.json` and `/private/tmp/agent-smith-claude-token-probe-FHjCnH/summary.json`. The per-process loopback exporter used `http/json` with prompt and tool detail disabled. [Documented API request events](https://code.claude.com/docs/en/monitoring-usage#api-request-event)
- **Claude decision.** Do not treat a notification, the final result line, a sleep, or a quiet collector as proof of complete delivery in a long-lived native host. Accept the host-scoped observed sum when a trustworthy invocation boundary and complete per-request source can be reconciled, with the isolated probe as a positive reference. A documented final query total can be used at that query's own boundary. For a native step inside a shared session, qualify an exact per-agent source, for example by reconciling request telemetry with final matched agent records, and retain the unavailable state when the installed host cannot provide the necessary evidence. The current notification value is final-request usage in the observed probe, so a trustworthy flat-step replacement needs the same whole-invocation evidence. Keep token reads and exporter configuration optional to execution. These are fail-closed conditions for reporting, not prerequisites to designing or implementing the rest of the fix. [Claude Agent fields](https://code.claude.com/docs/en/hooks#agent) · [SDK result scope](https://code.claude.com/docs/en/agent-sdk/typescript#sdkresultmessage)
- **Unattended acceptance.** Test positive and negative accounting behavior using the retained evidence and deterministic cases for missing, late, duplicated, and incorrectly attributed records. For host variants whose whole-invocation coverage cannot be established, test that the report gives an explicit reason and completion still proceeds. The user authorized implementation with evidence-backed decisions and no interaction. There is no need to obtain perfect exporter or billing telemetry across host variants before planning a version-bounded implementation with this fallback.
